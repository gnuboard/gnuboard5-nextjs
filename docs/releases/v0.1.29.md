첨부한 `gnuboard5-nextjs-v0.1.29.zip` 을 그누보드5 루트(`common.php` 가 있는 폴더)에 풀고, zip 안의 `INSTALL.md` 를 따라 주세요. GitHub 가 자동으로 만드는 Source code 압축은 설치용이 아닙니다.

## 고친 것 · 바뀐 것

- **움직이는 GIF · WebP · APNG 가 멈춘 그림이 되던 문제** — 웹 에디터(상품 후기 등)로 움직이는 GIF 를 올리면 첫 장면만 남았고, 움직이는 WebP 는 "Image decode failed" 로 올라가지 않았으며, APNG 는 첫 장면만 남았습니다. 이제 세 형식 모두 움직이는 채로 저장합니다.
  - 그림을 다시 그리지 않고 파일 구조를 조각 단위로 다시 짜서, 장면 · 반복 정보만 남기고 메타데이터(EXIF · XMP · ICC · 글자)와 파일 끝 뒤에 덧붙은 자료는 버립니다. APNG 는 모든 조각의 CRC 를 확인합니다.
  - 장면이 그림 밖에 있거나, 장면이 500장 · 전체 3억 화소를 넘거나, 스크립트 · SVG · HTML 표식이 남거나, 구조가 어긋나면 받지 않고 예전처럼 GD 로 다시 그립니다(움직임 없이 저장).
  - 움직이지 않는 PNG · WebP 는 예전과 똑같이 처리합니다.
- **고쳐 저장하며 본문에서 뺀 사진도 정리** — 글 · 댓글 · 상품 후기 · 상품 문의 · 1:1 문의(답변)를 고쳐 저장하면, 저장한 본문에 더는 없는 에디터 사진을 그 글에서 뗍니다. 바로 지우지 않고 `WEBAPP_EDITOR_TMP_KEEP_DAYS`(기본 3일) 뒤에 정리하며, 그 사이 같은 사진을 다시 넣어 저장하면 다시 붙습니다. 본문을 보내지 않은 수정은 건너뜁니다.
- **수정 이력 게시판의 사진 보존** — 글 수정 이력을 남기는 게시판(post-history)은 옛 판이 사진을 계속 쓰므로 고칠 때 사진을 떼지 않습니다. 이 게시판에서 글을 지우면 이력이 보관함에 남으므로, 글 자신의 사진은 지우지 않고 댓글 사진만 지웁니다(v0.1.28 에서는 보관된 판의 사진이 깨질 수 있었습니다).
- 내부: 1:1 문의 찾기와 글 수정 이력 경로를 별도 파일(`api/v1/qas_lookup.php`, `api/v1/post_revisions_route.php`)로 나눴습니다. 동작은 같습니다.

2. zip 을 같은 그누보드 루트에 덮어 풀고 `/api/v1/status` 에서 `schema.ok` 가 `true` 인지 봅니다. 이번 판은 DB 가 바뀌지 않습니다.
